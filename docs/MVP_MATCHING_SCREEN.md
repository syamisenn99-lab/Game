# MVP 照合画面 設計書 v0.1

対象: 探索フェーズの「リアルタイム報告 ↔ ノート照合・指示」画面（GDD §5）。
目的: **ドラッグ＆ドロップ照合の手触り**が面白いかを、最小構成で確かめる。
> 数値はすべて「仮の初期値」。プレイして調整する前提。Godot での動作は未検証（設計段階）。

---

## 1. この画面で検証したいこと

1. 通信テキストの語をノートへ運ぶ操作が、気持ちよく・緊迫感があるか
2. 制限時間が「焦り」を生みつつ、理不尽にならないか
3. 照合の正否が、ダイス判定に「効いている」と実感できるか
4. ノートの虫食いが埋まっていく達成感があるか

## 2. 画面レイアウト（1280×720 基準）

```
┌──────────────────────────────────────────────────────────┐
│ [上部バー] 冒険者名 / 階層 / 状況メモ      ⏳ 残り時間ゲージ │
├───────────────────────┬──────────────────────────────────┤
│                       │                                  │
│  通信ログ（左）        │   ノート（右・本）                │
│  ・冒険者の声が        │   ┌─ ページタブ ─┐              │
│    1行ずつ流れる       │   │ 植物 / 魔物 / 罠 / 遺物 │      │
│  ・重要語は            │   └──────────────┘              │
│    ハイライト＋下線     │   項目1: 毒キノコの見分け方        │
│    （ドラッグ可）       │   項目2: 鋭い爪の獣  [ ？？？ ]    │
│                       │   項目3: …                       │
├───────────────────────┴──────────────────────────────────┤
│ [下部] 指示パネル:  指示 [戦闘][探索][回避]                       │
│         主人公の反応テキスト（「待って、それは毒だ！」）            │
└──────────────────────────────────────────────────────────┘
```

- 机の質感の背景に、通信ログは「メモ用紙」、ノートは「開いた本」として配置。
- 見やすさ最優先: 文字サイズは大きめ、ハイライトは**色＋下線＋太字**の3重（色だけに依存しない）。
- 画面外の情報（所持品・資金など）は MVP では出さない。

## 3. 1イベントの流れ

```
[報告到着] ─→ [照合タイム（時間ゲージ減少）] ─→ [指示] ─→ [判定] ─→ [結果・ノート更新]
```

1. **報告到着**: 冒険者の声が**タイプライター表示**（一定速度）で通信ログに現れる。重要語は表示された瞬間からドラッグ可能。重要語がハイライト。同時に時間ゲージが始動。
2. **照合タイム**: 以下のどれかを行う。
   - **A. 照合ドロップ**: ハイライト語をノートの項目へドラッグ。
   - **B. 虫食い穴埋め**: 語（キーワードスタンプ）をノートの `[ ？？？ ]` へドロップ。
3. **指示**: 下部パネルで「能力値」を選ぶ（照合で得た答えに基づく）。MVPでは「方針（進む／退く／待つ）」は選ばせない。
4. **判定**: 目標値が決まり、`d20 + 冒険者の能力値` で成功判定（§6）。
5. **結果**: 成功/失敗の描写。照合で得た情報はノートに残る（更新・確定）。

> 時間切れ: 指示が未選択なら「無指示」として判定（§6）。冒険者は自力で動く。

## 4. 操作仕様

### 4.1 ドラッグ＆ドロップ
- **ドラッグ元**: 通信ログ中のハイライト語（キーワードチップ）。
- **ドロップ先**:
  - ノート項目（既存知識の照合）
  - 虫食い穴（新情報の確定）
- ドラッグ中: 語がカード状のプレビューに変わり、ドロップ可能な場所が**光る（可/不可で形状も変える）**。
  - 虫食いの穴は**大きめ（150×52）**にする。ドラッグ中は穴が青い枠でうっすら脈打ち、その上に乗せると**黄色く強く光る**（文字は変えない）。
  - 穴の上にいるときは項目全体の光は消える（「穴に入れる」と「項目に当てる」を別の選択肢として見分けられるように）。
- 離した場所が無効なら元の位置に戻る（ペナルティなし）。

### 4.2 ドロップ結果

| 操作 | 結果 | 演出 | コスト |
|---|---|---|---|
| 正しい項目へ | 照合成功。項目に印（スタンプ）、主人公のセリフ | 小さな効果音＋スタンプ | なし |
| 関係ない項目へ | 不一致 | 紙が揺れる／「違う気がする」 | **時間ゲージを一定量消費**（仮: 1.5秒） |
| 正しい虫食い穴へ | 穴が埋まり情報が確定 | インクがにじむ演出 | なし |
| 違う語を穴へ | 弾かれる | 「入らない」 | 時間ゲージ消費（仮: 1.5秒） |

- **照合に成功したら、下の指示パネルが金色に脈打って光り、3つのボタンに金色の枠が付く**（「次は指示を選ぶ」への誘導。文字は出さない）。指示を選ぶと消える。
- 当て推量の連打対策として、不一致は**時間を消費**する（ペナルティ以外の罰は与えない）。
- 正しい語を**ドロップしないまま**指示を出すこともできる（リスクを取る選択）。

### 4.3 クリック代替操作（アクセシビリティ）
- 語をクリックで選択 → 項目をクリックで確定。ドラッグが苦手でも遊べるようにする。

### 4.4 ノートの「不確か」さ
- ノート項目には信頼度がある: **確定**（青インク）／ **不確か**（鉛筆書き・又聞き）。
- 報告がノートと**食い違う**場合、項目が「訂正候補」として光る。語をドロップすると書き換わる（成長要素）。
- MVP では「虫食い」＋「1〜2件の食い違い」だけ実装する。

## 5. データ設計（Godot Resource を想定）

```gdscript
# 例（擬似）
class_name NoteEntry extends Resource
@export var id: StringName
@export var page: StringName        # "plants" / "monsters" / "traps"
@export var title: String
@export var body: String            # 虫食い箇所は "{blank:fire}" のように埋め込む
@export var blanks: Array[Blank]    # {id, answer_keyword}
@export var reliability: int        # 0=不確か 1=確定
@export var correct_stat: StringName # "evade" など、この項目で正しい指示

class_name Keyword extends Resource
@export var id: StringName          # "red_spot_mushroom"
@export var display: String
@export var targets: Array[StringName]  # 正しくドロップできる NoteEntry/Blank の id

class_name EventDef extends Resource
@export var report_lines: Array[String]  # キーワードは "[kw:id]青い斑点のキノコ[/kw]" 形式で埋め込み
@export var time_limit: float            # 秒
@export var base_target: int             # 判定の基準目標値
@export var entry_id: StringName         # このイベントで正解となるノート項目
@export var stat_required: StringName
```

- ログ内のキーワード記法は、パーサで `Keyword` に分解して `HFlowContainer` 上のチップに変換する。
- 冒険者・能力値は `Adventurer` Resource（`battle / explore / evade`）。

## 6. 判定ルール（仮）

```
target = base_target + modifier
roll   = d20 + adventurer.stat[chosen_stat]
成功: roll >= target
```

| 状況 | modifier（仮） |
|---|---|
| 正しい項目を照合し、正しい能力値で指示 | **−8**（ほぼ成功。ダイスが1のときだけ失敗） |
| 照合したが能力値だけ誤り | 0 |
| 誤った項目に基づく指示（読み間違い） | **+4** |
| 無指示（時間切れ） | +2 |

- 失敗時の影響は HP ではなく**持ち帰り報酬の減少**（失敗1回につき報酬の一定割合を減らす。仮: 10%）とする。大失敗は追加で減少。
- 大失敗（ナチュラル1）は罠発動など強い悪影響。逆に大成功は発見ボーナス。
- 調整のため、判定の数値は 1 つの定義ファイルに集約する。

## 7. 制限時間

- **イベントごとの時間ゲージ**（バーで表示）。MVP では 15〜30 秒を目安にする。
- 時間は「敵の接近」などの演出と連動して見た目を変える（バーが赤くなる、足音のテキスト）。
- 砂時計アイテム（後で追加）は `time_limit` を伸ばす乗算係数にする。
- 報告の表示速度は一定（読むのに必要な時間も制限時間に含む）。

## 8. MVP サンプルシナリオ（幼馴染・第1層）

| # | 報告（要約） | 照合 | 正解の指示 |
|---|---|---|---|
| 1 | 「青い斑点のキノコを見つけたよ」 | キーワード「青い斑点のキノコ」→ ノート「毒キノコの見分け方」にドロップ | 触らず避けて通る（指示: 回避） |
| 2 | 「爪の長い獣が来る！とっさに松明を振ったら、怯んで後ずさった！」（観察した事実の報告） | 「松明」→ 虫食い `[ ？？？ ]` に「火」スタンプ（冒険者が見た事実が根拠。推測では埋めない） | 押し返す（指示: 戦闘）。ノートが更新される |
| 3 | 「不気味な石像がある…」 | 「石像」→ ノート「石像の罠」にドロップ | 台座を調べて隠しスイッチを探す（指示: 探索） |
| 4 | 「さっきの爪の長い獣が、また来た！松明を向けたら、すぐに怯んだみたい…！」（制限時間15秒） | 2つ目で「火」を埋めていれば**照合済みで始まる**（魔物ページが自動で開き、項目が光り、指示パネルも光る）。埋めていなければ自分で照合する | 押し返す（指示: 戦闘）。ノートが育った効果を体験する |
| 5 | 「光る苔がびっしり…試しに触ってみたら、手がしびれてきた…！ノートには触っても無害って書いてあったよね？」 | ノートの「触っても無害」（又聞きの間違い）が**オレンジに脈打つ**。別のタブにあるときはタブ名に「●」。「触ってみたら、手がしびれて」をそこにドロップすると赤字の「触るとしびれる」に**訂正**される（ハンコは「訂正済」） | 離れて避ける（指示: 回避）。訂正はずっと残る |

- 1〜3 でチュートリアル、4 で「自分で埋めたノートが効く」成長を体験させる。5 で「ノートは間違っていることがある」と、その訂正を体験させる。
- **ノートの各項目には対処法を世界の中の言葉で書いておく**（例:「近づかず、触れないように避けて通ること」）。「戦闘」「探索」「回避」といった指示名そのものは書かない。ノートを読めば、どの指示が向くか分かるようにする。
- 傭兵（効率重視で語が単純）を2人目として足し、報告のクセによる違いを検証する。

## 9. Godot 実装メモ

### シーン構成（案）
```
MatchingScreen (Control)
├─ TopBar (HBoxContainer)       # 冒険者名・階層・TimerBar (ProgressBar)
├─ HSplit
│   ├─ CommLog (ScrollContainer → VBoxContainer → 行ごとの HFlowContainer)
│   └─ NoteBook (Control)
│        ├─ PageTabs (TabBar)
│        └─ EntryList (VBoxContainer → NoteEntryView × n)
└─ CommandPanel (VBoxContainer)  # 能力ボタン / 主人公セリフ
```

### ドラッグ＆ドロップ
- ドラッグ元: `KeywordChip`（Control）で `_get_drag_data(at_position)` を実装し、`set_drag_preview()` でプレビューを設定。
- ドロップ先: `NoteEntryView` と `BlankSlot` で `_can_drop_data()` / `_drop_data()` を実装。
- 判定は 1 か所の `MatchingController` に集約（UI は結果を表示するだけ）。シグナル例:
  `keyword_dropped(keyword_id, target_id)` → `match_resolved(result)`。
- 時間ゲージは `Timer`ではなく `_process(delta)` で減らし、不一致ペナルティを即座に引ける形にする。

### 先に作る順番（1〜2週間の目安・個人差あり）
1. 固定1イベントで、チップのドラッグ＆ドロップだけ動かす
2. 正否判定＋主人公セリフ＋時間消費
3. 虫食い穴埋め
4. 指示パネル＋ダイス判定
5. イベントを3〜4個つなげる（サンプルシナリオ）
6. 見た目の仕上げ（スタンプ・紙の揺れ・効果音）

## 10. 成功基準（プレイテストで見ること）

- [ ] 初見で、説明なしでも30秒以内にドラッグ操作を理解できる
- [ ] 正解をドロップした瞬間に「気持ちいい」と感じる
- [ ] 時間切れで「理不尽」ではなく「惜しい」と感じる
- [ ] 誤指示で失敗したとき、原因（読み間違い）を自分で理解できる
- [ ] ノートが成長した実感がある（虫食いが埋まる・訂正する）

## 11. 決定事項と未決事項

### 決定済み
| 項目 | 決定内容 |
|---|---|
| 報告の表示 | タイプライター表示（一定速度）。重要語は表示された瞬間からドラッグ可 |
| 指示の形 | MVPは**能力値のみ**を選ぶ（方針は後のバージョンで追加） |
| 失敗の影響 | **持ち帰り報酬の減少**（HP等は持たない） |
| 虫食いの埋め方 | 報告から拾った語を**その都度ドロップ**（スタンプ棚は後の拡張） |

### 未決
1. 画面解像度・フォントの方針（日本語フォント選定）。
2. タイプライター速度の初期値と、読み飛ばしの可否（クリックで即時全表示にするか）。
3. 報酬の減少割合（仮10%）と、成功時のボーナスの有無。
4. 能力値を選ぶ前に「照合が必須」か、「照合なしでも指示可（リスクあり）」か。現状は後者（§4.2）。

## 12. 冒険者の選択と、傭兵のシナリオ（実装済み）

ゲームを起動すると、まず「誰をガイドする？」の選択画面（準備フェーズの最初の一歩）が出る。選んだ冒険者のシナリオで探索が始まる。ノートは共通（ただし1回の探索ごとに初期状態から始まる）。

| 冒険者 | 能力（戦闘/探索/回避） | 報告のクセ | イベント数 |
|---|---|---|---|
| 幼なじみ | 3 / 4 / 3 | ふつう。見たことを素直に伝える | 5（キノコ、獣、石像、獣の再会、苔の食い違い） |
| 傭兵 | 5 / 2 / 3 | 短く事務的。「割に合うか」で判断。表示が速い（32文字/秒）。手がかりを「金にならん」と流す | 4（下表） |

| # | 傭兵の報告（要約） | 照合 | 正解の指示 | ねらい |
|---|---|---|---|---|
| 1 | コウモリ三体。戦っても報酬は出ない、迂回ルートを出せ | 「天井の群れ」→ ノート「岩穴の蝙蝠」 | 回避 | コスト重視の判断に、ノートの根拠を添える |
| 2 | 獣一体。松明を向けたら退いた。戦えば報酬に見合う | 「松明を向けたら、退いた」→ 虫食いに「火」 | 戦闘 | 事実が簡潔で照合しやすい。戦闘が得意 |
| 3 | 壁に模様。どうでもいい。床の石にも同じ模様があるが、金にならん | 「床の石にも同じ模様」→ ノート「壁や床の幾何学模様」（遺物ページ） | 探索 | **傭兵が流した手がかりを、プレイヤーが拾う** |
| 4 | 石像だ。壊せば早い。壊すぞ。止めるなら今だ | 「この石像」→ ノート「石像の罠」（壊すと作動する） | 探索 | **傭兵の判断を、ノートの知識で止める** |

- 傭兵は探索が苦手（2）なので、探索が正解のイベント（3・4）でも、照合しないと成功しにくい。
- ノートに4つ目のページ「遺物」を追加した（幾何学模様、古い石板）。

## 13. ノートの引き継ぎ（実装済み）

- 探索で**埋めた虫食い・訂正した記述**は、次の探索（別の冒険者でも）に引き継がれる。
- 引き継ぎ先のノートでは、最初から埋まった（訂正された）状態で表示される。
- あるイベントの正解の箇所が**すでに埋まっている**と、そのイベントは**照合済みで始まる**（ノートのページが自動で開き、項目が光り、指示パネルも光る。主人公が「あ、ノートに『火』って書いてある！」と言う）。
- 探索の終わりに「ノートに書けたこと: 「火」、「触るとしびれる」」を表示する。
- 選択画面に「ノートの育ち 1 / 2」と書けたことを出す。「ノートを最初に戻す」ボタン（誤操作防止のため2回押して確定）でリセットできる。
- 保存先: `user://notebook.json`（Godot のユーザーデータフォルダ。Windows なら `%APPDATA%\Godot\app_userdata\安楽椅子冒険者\`）。ゲームを閉じても残る。

### 仕組み
- `GameSession.filled_blanks`（埋まった箇所の id の辞書）を `MatchingState` が共有して読み書きする。
- 埋まった箇所があるイベントは、`MatchingState.begin_next_event()` が自動で `matched = true` にする。
- 引き継ぐのはノートの育ちだけ。報酬や進行状況は引き継がない（探索ごとに初期化）。

### 設計上の注意（今後）
- 引き継ぎが進むと、同じシナリオの照合の遊びは薄くなる（ノートが完成した状態で遊ぶと、ほぼ指示を選ぶだけになる）。
  → 引き継ぎが進んだ人向けに、新しい未知の情報（新しい虫食い・間違い）を足していく必要がある。
