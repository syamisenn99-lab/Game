# 冒険者会社（最小版）

中世ファンタジーの世界で、「冒険者を雇い、ギルドのクエストに派遣する会社」を経営するシミュレーション。
冒険者には毎月固定の給料を払い、クエスト報酬との差額が会社の利益になる。

最小版の内容：冒険者5人・職業3種・クエスト10件＋常設依頼1件・12週（給料日3回）。

## 起動方法

- Godot 4.6.3 で動作を確認した（4.3 以降で動くように書いている）。
- エディタの場合：Godot で `adventurer_company/project.godot` を開き、F5 で実行する（メインシーンは `scenes/main.tscn`）。
- コマンドラインの場合：

```sh
cd adventurer_company
godot --path .                    # 遊ぶ（乱数シードは毎回変わり、コンソールに表示される）
godot --path . -- --seed 123      # 乱数シードを固定して遊ぶ（同じ操作なら同じ展開になる）
```

## 操作方法

1. **掲示板（左）** から依頼の紙をクリックすると、**詳細パネル（右）** に依頼文・難易度・期間・報酬・推奨職業・必要評判が出る。
   - 評判が足りない依頼は、紙がグレーで「評判Nで受注可」と表示される。詳細は見られるが、派遣はできない。
   - 受注済みの紙には「受注中」のスタンプが押され、残り週数が出る。
   - 「常設」の札がついた緑っぽい紙は**常設依頼**。報酬は安いが、何度でも受けられる。評判が低いときに評判を稼ぐための依頼。
2. **「冒険者を派遣する」** を押すと、派遣パネルが開く。
   - 待機中の冒険者から1〜3人を選び、支度金（0G／30G／60G／100G）を選ぶ。
   - 選ぶたびに **成功率（辛勝以上の確率）** と5段階それぞれの確率、補正の内訳、必要な出目、報酬の期待値が更新される。
   - 「派遣決定」で派遣する。支度金はこのとき支払い、失敗しても戻らない。同じ週に何件でも派遣できる。
3. 画面下の **会社の名簿** で、全員の状態（待機中／派遣中（残りN週）／休養中（残りN週））をいつでも確認できる。
4. 上部バーの **「週を終える ▶」** を押すと、週が進む。
   - 期間が終わったクエストを判定し、**結果レポート** に出目・補正の内訳・判定値と難易度の差・結果・報酬・評判の変化が出る。
   - 負傷者が出たら、医療費 30G を負担するか（休養 −1週・評判 +2）を選ぶ。
   - 第4・8・12週の終わりは給料日。全員の月給を払えなければ倒産になる。
5. 第12週の給料日を払い切ればクリア。結果画面に、最終所持金・評判・成功数が出る。

## ルールの要点

- 判定値 = d20 + パーティ内で最も高い腕前 + 2×(追加メンバー数) + 職業一致 +3 + 支度金補正 + スキル補正
- 差 = 判定値 − 難易度

| 結果 | 差 | 報酬 | 評判 | その他 |
|---|---|---|---|---|
| 大成功 | +8 以上 | 150% | +3 | |
| 成功 | +3〜+7 | 100% | +2 | |
| 辛勝 | 0〜+2 | 80% | +1 | パーティの1人が軽傷（休養1週） |
| 失敗 | −5〜−1 | 0 | −1 | |
| 大失敗 | −6 以下 | 0 | −3 | パーティの1人が重傷（休養2週） |

- 確率は、全ての目（強運なら 20×20 = 400 通り）を数え上げて厳密に計算する。
- 画面の確率と実際の判定は、同じ補正の計算（`CheckRules.build_modifiers`）と同じ判定関数（`CheckRules.evaluate`）を通している。だから、表示と実際がズレることはない。
- 休養は「負傷した週の次の週」から数える。軽傷（1週）なら、次の週は派遣できず、その次の週から派遣できる。医療費を払って休養が0週になれば、次の週から派遣できる。
- 依頼は、出現した週を含めて3週のあいだ掲示される。各依頼は1回きり。
- **常設依頼**（街道の見回り）は、最終週まで掲示され続ける。完了しても掲示板に戻り、次の週からまた受けられる（同時に受けられるのは1組だけ）。報酬は10Gと安く、この依頼で上がる評判は15まで（15以上なら上がらない。失敗で下がるのは通常どおり）。序盤でつまずいた会社が、評判を立て直すための依頼。
- 支度金と医療費は、所持金が足りなければ選べない。倒産の判定は給料日だけで行う。
- 第12週の終わりに完了していない依頼は、報酬も評判の変化もない。

## 数値の調整（data/*.json）

コードを触らずに、`data/` の JSON を書き換えれば調整できる。読み込み時に検証して、おかしな値があれば画面とコンソールにエラーを出す。

### data/balance.json

| キー | 意味 |
|---|---|
| `initial_gold` / `initial_reputation` | 初期の所持金・評判 |
| `reputation_min` / `reputation_max` | 評判の範囲 |
| `total_weeks` / `weeks_per_month` | 全体の週数・1か月の週数（「N月目」の表示） |
| `payday_weeks` | 給料日の週（その週の終わりに支払う） |
| `party_min` / `party_max` | パーティの人数 |
| `dice_sides` | ダイスの面数 |
| `extra_member_bonus` | 追加メンバー1人あたりの補正 |
| `job_match_bonus` | 職業一致の補正 |
| `quest_listing_weeks` | 依頼が掲示される週数（出現週を含む） |
| `success_outcome` | この結果以上を「成功」とする（成功率・成功数） |
| `jobs` | 職業ID → 表示名 |
| `supply_tiers` | 支度金の段階（`cost` と `bonus`）。最初は cost 0 にする |
| `outcomes` | 5段階の結果。良い順に並べ、`min_diff`（この差以上）、`reward_rate`、`reputation`、`injury`（負傷ID、空なら負傷なし）を持つ。最後の段階の `min_diff` は `null`（下限なし） |
| `injuries` | 負傷ID → 名前と休養週数 |
| `medical` | 医療費（`cost`）、休養の短縮（`rest_reduction`）、評判（`reputation`） |

### data/adventurers.json

`id`、`name`、`job`（職業ID）、`ability`（腕前）、`salary`（月給）、`employment_type`（今回は全員 `"regular"`）、`skill`。

`skill.type` で効果が決まる（`value` はその強さ）：

| type | 効果 | 例 |
|---|---|---|
| `party_bonus` | パーティの判定 +value | 先読み（+2） |
| `supply_bonus` | 支度金を出したとき支度金補正 +value | 研究熱心（+1） |
| `advantage` | d20 を value 回振って高い方を使う | 強運（2） |
| `outcome_floor` | 結果が value（結果ID）より悪くならない | 鉄壁（`"failure"`） |
| `none` | 判定への効果なし | 薄給 |

### data/quests.json

`id`、`name`、`difficulty`、`weeks`、`reward`、`job`（推奨職業）、`required_reputation`、`appear_week`（掲示される週。省略すると1）、`description`（依頼文。`\n` で改行）。

常設依頼にするときは、次の2つも使う：

| キー | 意味 |
|---|---|
| `repeatable` | `true` なら常設依頼。期限切れにならず、完了すると次の週にまた受けられる |
| `reputation_cap` | この依頼で上がる評判の上限（省略すると上限なし）。下がる方には効かない。常設依頼以外にも使える |

## テストとバランス確認

```sh
cd adventurer_company
godot --headless --path . --import                                # 初回のみ（クラス名キャッシュの生成）
godot --headless --path . --script res://tests/run_tests.gd       # テスト
godot --headless --path . --script res://tools/balance_sim.gd -- --runs 1000 --seed 1
```

- `tests/run_tests.gd`：5段階の確率の合計が1になること、境界値（差 +8／+3／0／−5／−6）、鉄壁・強運・研究熱心が確率と実判定の両方に効くこと、給料日と倒産、休養と医療費、掲示期限、進行フック、シードによる再現、UI の流れ（派遣パネルの表示と実際の確率が一致するか、クリアまで進められるか）を確かめる。
- `tools/balance_sim.gd`：貪欲AI（`tools/greedy_ai.gd`）で何度もプレイし、クリア率、最終所持金の平均と分布、倒産した週の分布、**序盤（第1〜4週）に通常の依頼を何回失敗したかごとのクリア率**（挽回できるかの目安）、クエスト別の受注率（常設依頼は1プレイあたりの回数）と成功率（実際の結果と、派遣画面に出る予測の平均）を出す。
  - `--data <フォルダ>` を付けると、`data/` の代わりに別のフォルダの JSON を読む。`data/` を書き換えずに調整案を比べられる。
  - `--threshold 0.65`：AI が支度金を出し始める成功率。
  - AI のふるまい：受注できる依頼を報酬の高い順に見て、成功率が最も高い編成を選ぶ（同点なら人数が少ない方、次に月給の合計が安い方）。成功率が65%未満なら、65%に届く最小の支度金を出す（届かなければ出せる範囲で最大の支度金）。支度金と医療費は、次の給料日の支払額を残せる範囲でだけ使う。
- `tools/capture_screens.gd`：画面を自動で操作してスクリーンショットを撮る（表示崩れや文字化けの確認用。描画が必要なので `--headless` では動かない）。

```sh
xvfb-run -s "-screen 0 1280x720x24" godot --path . --rendering-driver opengl3 \
  --script res://tools/capture_screens.gd -- --seed 7 --out /tmp/screens
```

## 日本語フォント

`ui/theme.tres` のフォントは `SystemFont` で、OS にある日本語フォントを順に探す（Noto Sans CJK JP → Yu Gothic → Meiryo → Hiragino → IPA ゴシック など）。Linux の IPA ゴシック環境で、豆腐（□）にならずに表示できることを確認した。

配布用にエクスポートする前には、日本語フォント（例：Noto Sans JP、OFL ライセンス）を `assets/fonts/` に置いておくこと。そのうえで、`ui/theme.tres` の `default_font` をそのフォントファイルに差し替える（エディタでテーマを開いて、Default Font にドラッグするだけ）。

## 拡張用の口（今回は中身なし）

- **雇用形態**：冒険者は `employment_type` を持つ（今回は全員 `"regular"`）。月給は `GameController.salary_for()` を通して計算しているので、雇用形態ごとの計算はここに足せばよい。
- **伝令イベント**：`GameController.mission_week_hooks` に `Callable` を足すと、進行中のクエストごとに、毎週「残り週数を減らす直前」に `hook.call(controller, quest_state, report)` が呼ばれる。`report.events` に書いたものは結果レポートに表示される。
- **死亡**：負傷の重さは `balance.json` の `outcomes[].injury` と `injuries` の表で決まる。新しい重さを足すときの入口はここ。

## 仕様からの変更点

- **必要評判**：クエスト5〜10の必要評判を、仕様の 20/20/30/30/40/50 から **15/15/20/20/25/30** に下げた。評判は1件あたり最大+3（辛勝+1に医療費+2を足しても+3）しか増えない。そのため仕様の値だと、クエスト7（必要30）の掲示期限である第7週の時点でも評判は最大28で、クエスト7〜10を受注できなかった。
- **難易度と月給**：最初のバランスシミュレーション（1000回）でクリア率が100%になり、簡単すぎた。そこで、全クエストの難易度を **+2**、全員の月給を **1.5倍**（5G単位に丸める）にした。
  - 難易度：12 / 10 / 14 / 15 / 16 / 16 / 17 / 15 / 19 / 21
  - 月給：ガルド 90G、リーナ 60G、オズワルド 120G、トム 40G、ミラ 70G（合計 380G）
  - 調整後のシミュレーション（1000回、シード1〜1000）：クリア率 74.9%、クリアした回の最終所持金は平均 720G（中央値 660G）。倒産は第8週が 9.6%、第12週が 15.5%。
- **常設依頼の追加**：調整後のシミュレーションでは、序盤（第1〜4週）に通常の依頼を2回失敗するとクリア率が 11.8% まで落ち、挽回の手段がなかった。そこで、効率は悪いが評判を稼げる常設依頼「街道の見回り」（難易度14・1週・10G・評判は15まで）を追加した。
  - 評判の上限をつけないと、毎週の評判稼ぎで評判の関門がすべて開いてしまった（報酬10Gの1件だけでもクリア率97%超）。そこで、評判の低い会社だけが助かる形にした。
  - 追加後のシミュレーション（1000回、シード1〜1000）：クリア率 82.6%（追加前 74.9%）。序盤に2回失敗したときのクリア率は 42.6%（追加前 11.8%）。
